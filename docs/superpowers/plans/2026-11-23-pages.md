# Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the five screens of the event app, served as static pages from the existing Worker and deployed by GitHub Actions on merge to `main`:
- participant (`/`)
- projector (`/projector`)
- referee (`/ref`)
- race control and admin console (`/control`)

**Architecture:**
- **New package:** `packages/web` is a Vite multi-page app (Preact + TypeScript), with one HTML entry per page and shared client libraries for the live connection, clock sync, offline tap queue and state merging.
- **Serving:** the Worker serves `packages/web/dist` as Cloudflare static assets. Only `/api/*` runs Worker code.
- **Data:** pages talk to the server only through the existing API (`/api/login`, `/api/pair`, `/api/command`, `/api/ws`), plus three small read endpoints added in Task 3.
- **Pure logic is tested in Node:** selectors, the bracket model, clock offset, queue and reconnect policy.
- **Pages are tested with** `@testing-library/preact` on happy-dom, and the whole system with Playwright against `wrangler dev`.

**Tech Stack:** Vite, Preact, `@preact/signals`, `motion` (springs), `uqr` (QR codes as SVG), Vitest, `@testing-library/preact`, happy-dom, Playwright (preinstalled Chromium), GitHub Actions, Wrangler.

**Spec:** `docs/design.md`:
- §7 lists the pages and the plan-3 decisions.
- §5 covers timing and §5.1 penalties.
- §4 is the lifecycle, and §3.5 the ranking display.
- §11 covers deployment.

Server behaviour is in `packages/server/src/core/*` (views, commands) and `packages/server/src/hub.ts`.

**Build series:** plan 3 of 4. Plan 4 is the Companion module.

## Global Constraints

- **UX follows the `anthropic-skills:apple-design` skill** (the user's request):
  - Press feedback on pointer-down.
  - Springs with `bounce: 0` by default, from `motion`.
  - Interruptible animation; nothing blocks input during a transition.
  - System font with size-specific tracking.
  - Spacing in `rem`.
  - Translucent sticky headers (`backdrop-filter`).
  - Support for `prefers-reduced-motion`, `prefers-reduced-transparency` and `prefers-contrast`.
- **Colour tokens** live in `packages/web/src/styles/tokens.css`:
  - `--accent: #D71920`
  - Tier colours: `--tier-gold: #C9A227`, `--tier-silver: #A7AEB8`, `--tier-bronze: #B0723A`, `--tier-copper: #C46A4A`, `--tier-tin: #8D98A3`. Tiers past five reuse `--tier-tin`.
  - Light and dark values come from `prefers-color-scheme`.
  - The projector always uses the dark set.
- **Touch targets:**
  - At least 44 × 44 px everywhere.
  - Referee team buttons are at least 120 px tall (phone) and fill half the width (tablet).
  - The **+5s** button is at least 56 px, a different colour (neutral/outline, never the accent), and separated by at least 16 px from the team button.
- **Budget:** the participant page's JS is **≤ 60 KB gzipped**. Task 1 checks this with a build-size test.
- **Reconnect policy** (all pages):
  - Backoff starts at 1 s and doubles to a 30 s cap, with ±50 % random jitter, and resets after 10 s connected.
  - An HTTP 401 on upgrade, or a close with code 4401, stops reconnecting and shows "Signed out".
- **Clock sync** (referee, projector, console):
  - Ping every 5 s while the round is `open` or `running`, and every 30 s otherwise.
  - Offset = median of the 5 lowest-RTT samples among the last 15; for each sample, `t1 + rtt/2 − clientNow`.
  - `serverNow() = Date.now() + offset`.
- **Tap ids:** `crypto.randomUUID()`.
- **Offline queue:** stored under the localStorage key `r2f.tapQueue`. An entry is removed on an `ack ok`, or on a non-retryable error code: `already_finished`, `not_your_team`, `bad_timestamp`, `penalties_disabled`, `round_not_running`, `invalid`, `forbidden`. It is kept otherwise.
- **localStorage keys:** `r2f.team` (the participant's team id) and `r2f.bracketView` (`'cards' | 'diagram'`).
- Pages show only what the server sends. No page re-derives brackets, rankings or results.

## Review Focus

1. **Reconnect storm.** After a venue Wi-Fi blip, ~1,750 phones reconnect at once. Each must back off with jitter and never retry faster than 1 s, and a 401 must never cause a tight loop. Covered by tests in Task 2.
2. **A referee phone locks or sleeps mid-race and then wakes.**
   - Queued taps are sent exactly once.
   - The clock is re-synced before any new tap is stamped.
   - Queued taps survive a page reload.
   
   Covered by tests in Task 2 and Task 7.
3. **A participant's remembered team is renamed or removed.**
   - A rename shows the new name, because teams are remembered by id.
   - A removed team clears quietly back to search.
   
   Covered by tests in Task 4.
4. **The projector is left open for hours, or loses its connection.** On reconnect it shows the screen the server's snapshot says, and the clock is correct after re-sync. Covered by tests in Task 6.
5. **Double-clicks in the console.** A double-clicked correction, START, FINISH or Open-next-round sends **one** command. The button is disabled until the ack arrives. An `unlock_required` reply opens a confirm dialog listing `changedRounds`. Covered by tests in Task 8.

### Task 2: Client live libraries

**Files:**
- Create: `src/lib/backoff.ts`, `src/lib/live.ts`, `src/lib/clock.ts`, `src/lib/queue.ts`, `src/lib/publicState.ts`
- Test: `test/lib/*.test.ts` (fake WebSocket class, `vi.useFakeTimers()`)

**Interfaces:**
- `nextDelay(attempt: number, random: () => number): number`: `min(30000, 1000·2^attempt) · (0.5 + random())`, then clamped to at least 1000.
- `class LiveConnection`:
  - `constructor(opts: { url: string; onMessage(msg: ServerMessage): void; onStatus(s: 'connecting' | 'open' | 'offline' | 'signed-out'): void; WebSocketImpl?: typeof WebSocket; random?: () => number })`
  - `start()`, `stop()`
  - `send(msg: object)`
  - `command(cmd: object, timeoutMs = 10000): Promise<Ack>`: sends `{type:'cmd', id, cmd}` and resolves on the matching `ack`, or rejects with `'timeout' | 'offline'`
  - `type ServerMessage` is `{type:'snapshot', view}`, `{type:'round', update}`, `{type:'view', view}`, `{type:'ack', …}` or `{type:'pong', t0, t1}`
- `class ClockSync`:
  - `constructor(conn: { send(msg: object): void }, now = () => Date.now())`
  - `handlePong(msg)`, `offset(): number`, `serverNow(): number`, `synced(): boolean` (true once there are 3 samples)
  - `start(intervalMs)`, `setInterval(ms)`, `stop()`
- `class TapQueue`:
  - `constructor(storage: Storage, key = 'r2f.tapQueue')`
  - `add(entry: { clientTapId: string; cmd: object })`, `all()`
  - `settle(clientTapId: string, ack: Ack)`: removes the entry when `ok`, or when the code is non-retryable (Global Constraints)
  - `flush(send: (cmd) => Promise<Ack>)`: sends entries in order and stops at the first network failure
- `applySnapshot(view): PublicState` and `applyRoundUpdate(state: PublicState, update): PublicState`. The update replaces `round` and `projector`, and the races of round `update.round.current`.

- [ ] **Step 1: Write the failing tests.**
  - `nextDelay`:
    - attempt 0 with random 0 gives 1000 (clamped)
    - attempt 10 with random 1 gives 45000. Correction: the cap applies before jitter, so `30000 · 1.5 = 45000` is allowed. Assert `30000 · 1.5` as the exact maximum.
  - `LiveConnection`:
    - reconnect delays follow `nextDelay`
    - after 10 s open, the attempt counter resets
    - an upgrade 401 (simulate with an `error` before open plus a `signedOut` flag from a pre-check `fetch` of `/api/me`), or a close code 4401, gives status `signed-out` and **no** further connect attempts
    - `command()` resolves on the matching ack id and rejects `offline` if the socket closes first
  - `ClockSync`:
    - samples with RTTs 400, 20, 30, 25, 500 and so on give an offset from the 5 fastest samples' median, not skewed by the slow ones
    - `synced()` is false before 3 samples
  - `TapQueue`:
    - entries survive a new `TapQueue` on the same storage (reload)
    - `already_finished` removes the entry
    - a timeout keeps it
    - `flush` sends each entry once (Review Focus 2)
  - `applyRoundUpdate`: replaces only the current round's races and the round state.
